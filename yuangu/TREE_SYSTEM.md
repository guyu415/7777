# 任务 5：上庭交互与愿力树

## 场景流程

新游戏从 `courtAwake` 进入。点击继续到 `courtHub`，操作四个独立场景目标：

1. 愿力树：查看阶外微光；保存 `court-tree-seen`。
2. 镂空金铃：两种感应尝试均只得到强弱和性质，完成后保存 `court-bell-learned`。
3. 容衡：以三条短句和三个玩家操作交代感知边界、收取不等于应允、巡视期限与命数禁令，保存规则标记。
4. 落凡台：规则完成后才能操作，进入原有 `prologueDescent`；既有战场收取、地图教学、五地探索及沙暴分支继续使用。

查看与教学不收取行动点、不推进探索时间。上庭地图不能用于调查或等候跳过流程。重复查看物件不发放额外愿力或隐藏分。

沙海 `sahaiEnd` 的原有文字保留，新增返回上庭选项；到达结尾时只解锁归路，点击后才返回。归庭选择“将本轮愿力归入树中”后生成一片 `sahai-001` 叶子。即使行动点为 0 也能完成，既有愿力总数不重复加算，落凡台在本轮归庭后不可重走。

## 五类记录

| 分类 | 记录 |
| --- | --- |
| 枝叶 | 归庭归档前无叶；归档后第一片叶可点击，查看本轮收取批次与相关卡片 |
| 微光 | 来源与愿力性质；未经表达的愿文不渲染，也没有读取按钮 |
| 根系 | 已收取总量、本次有明确记录的收取、待归庭/已入树状态及用途 |
| 年轮 | 已发生的苏醒、感应、下凡、收取、风起、倾听、归庭、初叶等里程碑 |
| 归档 | 已明确表达或完成收取的卡片；区分已表达/已收取/未应允 |

愿望是所求，愿力是由此形成的力量。收取不会提供读心能力。即使因“已收取”而生成一张可打开的记录卡，未经表达的愿文仍为 `null`，界面显示“尚无主动表达，愿文不可见”。

具体愿文只由已读节点 `node:prologueHear`、`node:sahaiLily` 或旧版 `node:lily` 解锁。进入节点但尚未显示全文，不提前提供愿文；打开面板会按原有行为补全当前对话，再生成记录视图。铃兰卡片标注“已表达、未收取、未应允”，不混入战后愿力收取量。

## 数据与程序分工

- `dist/court.js`：上庭剧情节点、四目标的行动与条件、归庭行动和归路事件。
- `dist/tree-data.js`：愿文、来源、愿力性质、解锁条件与初叶批次的独立剧情数据。
- `dist/wish-tree.js`：从现有周目状态生成五类记录的纯函数，不读写浏览器存储。
- `dist/tree-panel.js`：分类面板、叶片详情、愿望卡片及返回按钮。
- `dist/app.js`：沿用原渲染与输入，新增上庭场景目标及与“随身”分开的“愿力树”入口。
- `dist/engine-core.js`：本轮无修改。

原 schema v2、故事 ID、四个存档键、状态字段不变。不新增树专用存储或独立进度；所有解锁均由既有 `flags`、`visited`、`readEvents` 与一次性标记派生，随原存读档及清档操作生效。读较早的档案会回到该档案的树记录状态。任务 3 探索档和任务 4 线性序章档仍可原位继续；旧初始愿力仅作未记明愿文的收取记录，不能据此反推出心愿。
