# 状态与事件系统 / v2

在原工程增量扩展。所有状态可存档；没有网络、聊天模型、API 或后端。

## 状态字段

| 类型 | 字段 | 含义 |
| --- | --- | --- |
| 公开 | `minutes` | 从首日 00:00 开始的绝对分钟。界面显示日、十二时辰与 HH:MM |
| 公开 | `ap` | 剩余行动点，0–1000 |
| 公开 | `wish` | 已收取愿力，0–1000000。动作不把它当作可消费货币 |
| 隐藏 | `hidden.xunxu` | 循序，0–100 |
| 隐藏 | `hidden.rushi` | 入世，0–100 |
| 隐藏 | `hidden.yuejie` | 越界，0–100 |
| 隐藏 | `hidden.rongAwareness` | 容衡察觉，0–100 |
| 隐藏 | `hidden.wuImpression` | 无谌初印象，−100–100 |
| 其他 | `inventory` | 物品 ID → 数量（1–999，0 时删除） |
| 其他 | `readEvents` | 完整显示过的对话 `node:<id>` 和事件 ID；仅触发、尚未读完的文本不计已读 |
| 其他 | `onceEvents` | 已触发的一次性事件 ID，触发时立即写入 |
| 其他 | `flags` | 剧情标记与旧版一次选项标记 |
| 其他 | `eventLocks` | 互斥组 → 已选择事件或动作 ID |
| 其他 | `unlockedLocations` | 已解锁场景 ID；目前所在地点始终保留 |
| 调度 | `rngSeed` | 可存档的随机种子；读取同一存档并做同一选择会得出同一结果 |
| 调度 | `activeEvent` / `pendingTransition` | 插入事件及尚待推进的时间/目标，支持事件中途存读档 |
| 调度 | `entrySerial` / `eventLog` | 当前场景进入序号与最近 200 次事件触发记录，避免同次进入反复抽取 |

普通界面不显示隐藏值、互斥锁或原始状态。公开“随身”面板过滤标记为 `private` 的制作事件。

## 数据分工

- `story.js` 定义人物、物品、隐藏字段、初始状态、场景、选项和文字。
- `events.js` 定义事件条件和效果；更换规则无需修改引擎。
- `engine-core.js` 负责条件判断、事件优先级、结算和存档迁移。

事件样例：

```js
{
  id: 'example', title: '示例事件', once: true,
  when: {
    nodes: ['observe'],
    stats: { rushi: { gte: 1 } },
    notReadEvents: ['node:lily']
  },
  requiresItems: { goldBell: 1 },
  timeWindow: { start: 900, end: 1020 },
  mutex: 'example-group',
  effects: { hidden: { xunxu: 1 }, flags: ['example-finished'] },
  target: 'asideWind'
}
```

`when` 支持 `all` / `any` / `not` 组合，以及 `nodes`、`scenes`、`stats`（数字等于或 eq/gte/lte/gt/lt）、`items`、`time`、`flags`、`readEvents`、`onceEvents`、`unlockedLocations` 和四种列表的 `notXxx` 反条件。条件不通过不会收费、写标记或推进时间。选项同样可使用 `when`、`requiresItems`、`timeWindow`、`mutex`。

`requiresItems` 检查数量，不自动消耗物品；消耗可另设 `effects.items: { itemId: -1 }`。效果支持 `ap` / `wish` 增量、`hidden` 增量、`items` 增量、`flags` / `removeFlags`、`unlock` / `lock`。本例不提供愿力消费动作。隐藏分数、消耗与时程都是制作样例，不是附件的人物关系定论。

## 事件种类与优先级

1. **固定时刻主线**：`forcedAt` 为绝对分钟。推进动作跨过指定时刻时先停在触发点，优先于普通、条件及随机事件。按时刻从早到晚，同一时刻按 `priority` 降序执行。存档已经晚于指定时刻时，符合条件的未触发主线会在当前时刻补触发，不倒退时间。
2. **普通/条件事件**：每次到达节点、调试应用数值或重新检查时，按 `priority` 降序判断。没有 `target` 的事件仅应用效果；有 `target` 的事件插入对应对话。
3. **权重随机事件**：同一 `pool` 中先过滤不满足条件或权重 ≤0 的候选，再按权重抽取一个。一个池在同次进入只抽一次。`mutex` 可进一步保证整个周目只选择这一组中的一个结果。随机状态跟随存档，不能靠刷新重抽。

事件默认一次触发；可显式设置 `once: false` 使其在之后新的节点进入时再触发。固定事件始终只触发一次。`mutex` 为周目级互斥锁，同组其他事件之后无法触发。

`timeWindow` 使用每天的分钟窗 `[start,end)`，包含开始、不含结束，支持跨午夜（例如 start:1380/end:60）。`forcedAt` 则包含日期，不是每日循环。固定事件的时窗按预计触发时刻判断。

插入节点需指定 `resume: true`。没有 `resumeTo` 时，读完后返回被打断位置，剩余计时继续；跨越多个固定事件也逐一停靠。配置 `resumeTo` 时，强制改道主线，取消余下行程和原目标，已支付行动点不退，不额外支付一次。这两种情况都随存档保存。

## 制作面板

显式访问 `?debug=1` 后才显示“制作调试”，不开启永久偏好。可以调公开/隐藏数值、日期、时刻、物品和地点，查看一次标记、互斥状态、事件状态与随机种子，清空本游戏四个档位。面板清档不清其他应用数据，也不清文字速度；确认后退出当前周目，避免自动存档立刻重建。

调时向前会经过事件调度；强制主线可能让最终时间停在触发点。向后调时不会清除一次标记。插入事件未结束时允许调分数与物品，禁止修改时间，以保留尚未完成的时间队列。无效输入整批拒绝，不部分写入。
