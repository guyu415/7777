# 《愿骨》游戏接手规则

本工作区是现有静态视觉小说游戏。用户要求改游戏时，直接编辑实际 HTML、CSS、JS 或剧情数据文件，不能只提供一段替换文案，不能把世界观资料当成不存在程序的证据。

仓库固定为 guyu415/7777，游戏分支为 yuangu，路径为 yuangu/。当前默认分支属于聊天 app；不要在默认分支搜不到游戏后断言游戏不存在。只在游戏目录内工作，不修改仓库根目录的 Eunoia 项目。

先读 先读这个_游戏交接.md、package.json、README.md，并检查 dist/index.html 与 dist/story.js 的实际依赖。现有代码优先于 README 的过往版本描述。

## 工作方式

- 日常沟通简短、口语化。说明完成结果时说清改了什么、对应文件和验证结果。
- 沿用现有框架与文件组织。不要重做一个新游戏代替修订。
- 写剧情时沿用中文第二人称“你”指代苑，保持各人物独立声口、认知边界和已有因果。愿力不能读心。
- 完整剧情设定保留在用户的 Kelivo 工作区，不在公开仓库。读取用户当地的最新设定；用户提供的明确新修订优先，未定悬念不要擅自补全。
- 原地改对话时，保留稳定节点 ID、next、target、条件、once、flags、互斥、消耗与读档兼容。新增节点要检查全部跳转和汇合点。
- 保留现有图片与字体、透明图层、移动端横屏适配和点击区域，除非用户要求改它们。
- 无需把现有功能改写成通用网页面板或卡片布局。延续《愿骨》的月白、墨青、旧金与淡冰蓝设计。
- 修改前查看工作区已有变化，保留用户和其他模型的未提交修改。
- 有 Node.js 时按改动运行相关测试，完整回归命令是 npm test。无环境时说明未验证，不能报通过。
- 不清空用户存档，不随意改 localStorage 键名和数据格式。
- 不自动清掉用户现有资产，不因为需要部署就编造权限或发布成功。

只修改本地源码不会更新原 ChatGPT Sites 网址。用户要求可游玩结果时，在当前环境实际支持的方式下提供预览、完整运行文件或部署结果，并清楚区分它们。
